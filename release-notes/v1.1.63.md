## 找到那个 toast 了

你说 Termux 有 root —— 那我直接读了 App 的私有日志
（`/data/data/com.linuxwff.pigapp/files/logs/app.1.log`），你 10:53 那一段是这样的：

```
10:53:31 [->] {"type":"relay_session_delete","path":".../2026-10-27T03-34-56-762Z_...jsonl"}
10:53:31 [<-] {"type":"relay_session_deleted", ...}
10:53:31 [<-] {"type":"relay_log","source":"relay","level":"error",
               "message":"pig exited: code=143 err=exit status 143 path=\"...\""}
```

所以那个 toast 是：

```
relay: pig exited: code=143 err=exit status 143 path="…"
```

## 为什么会出现

- 删除一个会话 / 从一个会话切走时，relay 会**主动停掉那个会话空闲的 pig 进程**（SIGTERM → 退出码 143）。
  这是设计如此，不是故障。
- 但 relay 把「进程退出」统一记成 `level=error`（`logLevel()` 里有一条规则：消息含 `exited` 就算 error），
  而 App 对**每一条 relay error 都弹 toast** → 一次正常的停止就变成了红色报错。
- 所以：你删会话 → 停进程 → toast；再切会话 → 又停上一个 → 又一个 toast。看起来像「切会话就报错」。

## 修法（v1.1.63）

- relay 的 `pigProcess` 记住「这次是我们自己让它停的」，这种退出记成
  `pig stopped: code=143 …`（info 级），不再当错误；
- App 也顺手过滤 `code=143` / `signal: terminated` / `pig stopped`，这样即使 relay 还没更新也不弹。

顺便：上一版（1.1.62）加的 toast 日志也保留了，以后再有什么一闪而过的提示都能在日志里查到。

## 升级

装 `app-release.apk`（1.1.63），relay 也在同一个包里更新（这次两边都改了）——
装完后在 App 里「设置 → 重启 relay」，新的 relay 才会生效。
