## 「检查更新」不再消耗 GitHub API 额度

`api.github.com` 未认证时按 **IP 限制 60 次/小时**，而移动网络下很多人共用一个出口
IP，所以更新检查会莫名提示「GitHub 限流」。

现在按顺序取数据，只有最后一步才用 API：

1. `releases.atom` —— 普通页面，不算 API 额度，能拿到 tag、链接和更新说明；
2. `releases/latest` 的跳转 —— 只取 tag（atom 被墙时用）；
3. `api.github.com` —— 仅当前两者都不通。

其他改动：

- 结果缓存 5 分钟，连点「检查更新」不会重复请求；
- 真遇到 403/429 时按 `retry-after` / `x-ratelimit-reset` 显示「约 N 分钟后可再试」，
  不再是一句笼统的失败；
- 安装脚本的 API 兜底支持 `PIG_GITHUB_TOKEN`（公开仓库无需任何 scope），把额度提到
  5000 次/小时——适用于 github.com 连不上、只有 API 主机能通的网络。

## 下载被限速/限流怎么办

release 资产（APK、relay）本身是普通下载，不占 API 额度；如果仍返回 429/被限速：

```sh
PIG_RELAY_MIRRORS="https://ghfast.top/ " sh install-termux.sh v1.1.49
```

`PIG_RELAY_MIRRORS` 是空格分隔的 URL 前缀，依次重试；脚本本体也可以用 jsDelivr 拉取。

## 升级

1. 装 `app-release.apk`（1.1.49）；
2. Termux 里重跑安装命令；
3. App → 设置 → 重启 relay。
