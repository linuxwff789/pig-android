## 真凶找到了：`HttpURLConnection` 根本不让发 PROPFIND / MKCOL

你导出的日志里写得很清楚：

```
[webdav] sync now tapped: ready=true relay=true backupRemote=true busy=false
[webdav] backup start: http://127.0.0.1:5244 dir=pig-backups keep=7
[webdav] backup failed: ProtocolException: Expected one of [OPTIONS, GET, HEAD, POST,
PUT, DELETE, TRACE, PATCH] but was MKCOL
```

- **打包是好的**（relay 那边 0.16 秒传完 1.28 MB）
- 但 `java.net.HttpURLConnection` 只允许白名单里的方法，`MKCOL`（建目录）和
  `PROPFIND`（测试连接 / 列远端备份 / 恢复下载）**全被本地拒绝**，请求根本没发出去
- 所以「测试连接」「立即备份」「远端备份」「恢复」「定时备份」其实一直都没工作过

### 修法

改用 **OkHttp** 发请求（新增一个依赖），它允许任意方法：

- PROPFIND 带 XML body、Depth 头；MKCOL 建目录；PUT 上传；GET 流式下载
- 重定向仍然手动跟随（保留方法和 body）
- 「忽略证书错误」只作用于这个客户端（按 TLS 模式缓存，不污染全局）
- 地址没写协议头会直接提示；`404/405` 会加上提示：**地址可能要写到 WebDAV 路径**

### 你的地址要改

我在 Termux 里对你那台 WebDAV 探了一下：

| 地址 | PROPFIND |
|---|---|
| `http://127.0.0.1:5244/` | **405** |
| `http://127.0.0.1:5244/dav/` | **401**（正常，需要认证） |

你配的是 `http://127.0.0.1:5244`（这是 AList 的网页端口根路径），WebDAV 实际挂在
**`/dav`**。所以请把服务器地址改成：

```
http://127.0.0.1:5244/dav
```

用户名/密码填 AList 的账号（不是网页登录的 token）。改完先点「测试连接」，再点「立即同步」。
