## 安装过程不再「以为装好了」

第一次安装时，App 可能在 relay 二进制刚落地、Go 还没装、扩展还没编译的时候就
连上 relay 并启动 pig。结果是组件不全（没有 `/plan`、`/provider-ui`、自定义端点），
用户以为装好了，一用才发现不行。

- 安装脚本先跑 `pig-relay --prepare` 解出并注册内置扩展，再探测；探测不只看
  `success:true`，还会检查 `/plan`、`provider-ui`、`custom-endpoints` 是否真的在列表里。
- 安装脚本拆成 **9 个编号阶段**：环境、curl、Termux 开关、pig、Go、relay、UI 目录、
  扩展编译、校验；每个阶段写入 `~/.pig/install-status.json`
  （`state` / `step` / `total` / `message` / `updated`）。
- relay 1.1.36 在 `state=running` 时**不启动 pig**，丢开 agent RPC（ping、UI、备份等
  仍然工作），并把阶段以 `relay_install` 帧转给 App；`done` 后才放行。
- App 设置对话框显示 **步骤 N/9 · 阶段说明** 和真实进度条；relay 出现之前仍按时间
  给粗略提示。`done` 后自动重发 `get_state` / `get_messages` / `get_available_models`，
  不用手动重试。
- 任何关键阶段失败（找不到 pig、relay 版本不对、扩展加载不了）都会写
  `state=error` 并以非 0 退出；App 显示失败原因，不会再连到一个半成品后端。
  脚本异常退出（`set -e`）也会由 trap 写成 `error`，不会留下永远 `running` 的状态。
- 状态超过 45 分钟视为过期，避免一次崩溃的安装把 agent 永久锁住。

## 升级

1. 装 `app-release.apk`（1.1.36）；
2. Termux 里重跑安装命令（`install-termux.sh` 现在会输出 `[n/9]` 阶段，
   并在扩展真正加载成功后才报完成）；
3. App → 设置 → 重启 relay。
