## 代码审查后的一轮修复（App + relay）

### 会话 / 聊天
- **新会话不再回填旧记录**：`get_messages` 在后台构建历史期间如果用户新建/切换了会话，
  旧转录不会再被画到新会话上（新增 session epoch 校验，补上 v1.1.68.2 没覆盖的一条竞态）。
- **长回答自动跟随到底部**：之前 `scrollToItem(最后一条)` 会把长消息的*顶部*贴到屏幕上，
  流式输出看起来像卡住；「回到底部」按钮同样修正。
- **草稿不会在发送失败时消失**：没有可用模型时 `sendPrompt` 会被拒绝，但输入框之前仍被清空。
- 工具卡展开、选择文本状态改用 `rememberSaveable`，滚出屏幕再回来不会自动收起；
  发送/排队按钮和工具模式芯片改用 `combinedClickable`，长按不再被每次重组打断，TalkBack 也能用。
- 队列里两条相同文字的消息会各自认领自己的气泡，删除/编辑不会再留下幽灵气泡。

### 安全 / 导入
- **UI pack 不能再伪造 RPC 类型**：`params` 里的 `type`/`id` 一律忽略，堵住「声明白名单动作、
  实际调用 `relay_session_purge`」的注入。
- zip/目录导入增加总量（24 MB）、单文件、条目数和目录深度上限，失败时清理暂存目录；
  目录导入拒绝 `..`、`/`、`\` 等显示名，避免写出暂存目录。
- 当前 pack 即使隐藏「UI pack 管理」入口，设置里仍保留一条兜底入口。
- WebDAV 重定向不允许跨主机或 HTTPS→HTTP，避免把 NAS 密码交给别的服务器；
  恢复完成后删除下载到 cache 的归档。

### 备份 / 恢复
- socket 自己断开时立即唤醒等待中的导出/恢复，不再白等 10 分钟并卡住所有备份。
- 恢复失败会主动断开、让 relay 清掉 busy 状态，并自动重连。
- 恢复先停掉 pig 进程再解压，避免运行中的回合把恢复出的会话/设置覆盖；
  解压有总字节与条目数预算（防 gzip 炸弹）。
- relay 只接受带 id 和 sha256 的恢复分片；旧分片不会追加到新恢复里。
- 备份/恢复进度改在主线程发布，不再和流式输出互相覆盖 UI 状态。

### relay / 网络
- `switch_session` 校验路径；`settings.json` 读写加锁并使用唯一临时文件。
- pig 单帧超过 64 MB 时直接停掉该 agent 并通知 App，不再「假活」。
- `relay_restart` 失败会回错误，运行中的回合会拒绝重启。
- 连接写入 20s 超时、客户端单帧 32 MB 上限；token 比较改为定长 hash，日志不再打印 token。
- provider 保存的 20s 网络请求移出读循环；`!command` 超时会真正杀掉子进程；错误信息里的 API key 打码。

### 其他
- 关闭 Android 自动备份（token / WebDAV 密码不再进云备份）。
- release 构建没有正式 keystore 时直接失败，不再静默使用仓库里的公开调试键。
- 修正预发布版本的比较逻辑；新增版本比较单测、relay 恢复/解压/detach 测试和 plan 命令策略测试。

装 `app-release.apk` 即可；**relay 有改动，请在 App 里点「更新 Termux 组件」或重跑安装脚本后重启 relay**。
