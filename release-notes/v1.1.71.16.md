## v1.1.71.16：relay 不再静默丢帧

接 v1.1.71.15 那版的 app 侧兜底，这次从源头补两处（只动 `pig-relay`）：

- **写失败就断开连接**：以前 relay 写客户端出错只记一个被忽略的 error，连接还留着 —— app 既收不到那一帧，也不知道自己漏了，更不会去重拉历史。现在写失败立刻关连接，app 重连后的 `relay_hello` 会触发 `needsHistory`，自动把会话重读一遍。
- **补发最后一帧状态迁移**：没有客户端时（app 在后台、正要重连、刚切会话），`message_end` / `agent_end` 这类"只说一次"的帧以前直接丢进 `send` 的 `out == nil → return nil`。现在每个会话缓存最后一条未送达的这类帧，重连时补发一次，气泡就能正常收尾。超过 16 MiB 的帧（通常带图片）不缓存，交给重连后的历史重读。

两个新测试覆盖：只缓存状态迁移帧、补发一次后清空。

日志里可以确认：relay 侧 `dropping client after write failure: …`。
