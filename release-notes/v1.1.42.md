## 供应商刷新失败后，不再「等一会儿才出现模型」

刷新的两条路径不一样：

1. 点「刷新模型列表」→ relay 立刻请求 `{baseUrl}/models`；
2. 保存后 → pig 的 `custom-endpoints` 扩展在会话启动时**再抓一次**并注册。

第一次请求遇到超时、5xx，或者新增供应商时 key 还没填，就会报错；但保存后扩展
抓成功，模型列表就晚一步出现在模型选择器里——就是“先报错、过一会又有了”。

- **保存 auto 且没有缓存时，relay 自己抓一次**并写入 `custom-endpoints.cache.json`，
  所以保存完成时模型就已经就绪；抓取失败也会保存，并提示「pig 启动时会再试」。
- 刷新失败的错误消息后面会提示：**可以先保存**（保存会重试，pig 启动也会重试）。
- 编辑已有供应商时留空 key 会继续使用已保存的 key；新增供应商请先填 key 再刷新。

## 升级

1. 装 `app-release.apk`（1.1.42）；
2. Termux 里重跑安装命令；
3. App → 设置 → 重启 relay。
