## 干净设备首次安装就能用「模型供应商」

这个版本把 `pigkit` 扩展模块（`provider-ui`、`custom-endpoints`、`model-speed`、`pi-memory`、`questionnaire`、`codegraph`、`pi-permission-system`、`reload-runtime`）**内嵌进了 relay 二进制**。以前它们只存在于「从备份恢复」的设备上：一键安装装出来的后端只有内置命令，App 里既没有「模型供应商」入口，也没有 `/endpoints`。

现在 relay 首次启动会把源码写到 `~/.pig/agent/pigkit/<包名>/`，并把 `pigkit/<包名>` 注册进 `settings.json`：

- 不需要联网、不需要额外下载（Go 工具链仍用于编译：`pkg install golang`）；
- 幂等：重复启动不会重复注册；
- 只重写内容变化过的文件，每个包写 `.embedded-hash` 标记，旧版残留会被清掉；
- **没有标记的包目录视为用户自己的**：不覆盖、也不注册（手改过的扩展是安全的）；
- 已有同目录 / 同名（含 `npm:` 前缀）/ 其它路径提供同一个包时跳过，避免命令注册两次。

验证（全新 HOME，等同于干净手机）：relay 解出 8 个包 → `get_commands` 返回 17 条命令，含 `provider-ui` / `endpoints` / `plan` → `/provider-ui` 写出 `~/.pig/android-ui/nav.json` 与 `windows/providers.json`。

## 修复

- **全新 Termux 上「一键安装」不再静默失败**：`allow-external-apps=false` 时 Termux 会在 exec 之前就拒绝 `RUN_COMMAND`，只把原因写进结果 PendingIntent。App 现在带 `PendingIntent`（`RunCommandReceiver`）读结果，被拦截时立刻给出「复制命令并打开 Termux」并停止重试 —— 以前要等 24 次重试才报一句笼统的 `connection refused`，而且每次重试都刷一条 Termux 通知。
- **安装有进度了**：设置对话框显示进度条 + 已用时间 + 分阶段文案（下载脚本 → 装 pig → 装 Go / 构建扩展 → 超过 12 分钟提醒去 Termux 看日志），relay 一答上就自动切到已连接。
- **扩展没加载时会说清楚**：`get_commands` 之后校验 UI pack 里 `nav.json` 用到的扩展命令是否真的注册；缺失时红条提示「在 Termux 里跑 `pig update`（缺 Go 先 `pkg install golang`）」，并且不再把 `ext:` 动作当聊天消息发出去 —— 以前那会变成 `prompt failed: No API key found for the selected model`。
- **安装脚本自检**：装完用 RPC 探一次 `pig` 的 `get_extensions`，扩展编译不出来就当场报错，而不是过一阵变成「只有内置命令」。
- relay 在 `ensureAgent` 失败时不再静默丢帧，会给客户端回一个 `success: false` 的 response。

## 升级

1. 安装 `app-release.apk`（1.1.30）；
2. Termux 里重跑一次安装脚本（或在 App 里按重试）：relay 换成 1.1.30 后需要重启（App：设置 → 重启 relay）才会加载内嵌的 pigkit。

### English

`pigkit` — the module behind the app's own 模型供应商 window, plus custom endpoints, model speed, memory, questionnaire and codegraph — now ships inside the relay binary. On first start it is written to `~/.pig/agent/pigkit/` and registered as `pigkit/<name>` in `settings.json`, so a clean Termux gets the provider UI without restoring a backup. Directories without the relay's `.embedded-hash` marker are left untouched and a package already provided from elsewhere is never registered twice.

Also in this release: `RUN_COMMAND` results are read back, so a Termux policy refusal (`allow-external-apps=false`) surfaces immediately with the manual "copy command and open Termux" path instead of a silent install; the setup dialog shows staged install progress; an unregistered UI-pack action no longer turns into a chat message ("No API key found…") but names the missing extension; and `install-termux.sh` verifies at the end that pig actually loads its extensions.
