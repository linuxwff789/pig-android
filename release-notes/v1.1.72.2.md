## v1.1.72.2：WebDAV 把文件重定向到网盘直链时，不再直接失败

增量备份的第一步是读服务器上的 `pig-index.json`。如果 WebDAV 是 AList 挂载的
网盘（Google Drive、S3 等），读取文件会收到一个指向存储方的 302。旧逻辑一律
拒绝跨主机重定向，于是备份在第一步就失败：

```
拒绝跨主机重定向：linuxwff.eu.cc -> www.googleapis.com
```

现在：

- 只有 **GET/HEAD** 会跟随跨主机重定向，并在跟随前**丢掉 WebDAV 的
  Authorization**（密码只属于这台 WebDAV，不会发给 Google）。
- **上传、删除**仍然拒绝跨主机重放，避免把备份或删除请求发到第三方。
- HTTPS 重定向到明文 HTTP 仍然拒绝。

注意：这只解决"读索引/下载备份"的第一步。如果 AList 的网盘存储本身缺少
API key，直链会返回 `403 missing a valid API key`，需要在 AList 后台补齐
API key、开启代理下载，或者把备份目录换到 AList 的本地存储。relay 不需要更新。
