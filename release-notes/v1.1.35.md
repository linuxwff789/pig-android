## 导入备份不再把 pig 弄成「疯狂报错」

上一版恢复一个来自开发机 checkout 的备份时，备份里的 `settings.json` 会带回：

```json
"packages": [ ..., "../../dev/pig-android/extensions/plan" ]
```

而 relay 自己也会安装 `~/.pig/agent/extensions/plan`，于是 pig 每次启动都退出：

```
Flag "--plan" conflicts with ~/.pig/agent/extensions/plan
```

App 只能看到反复重连/报错。

- 恢复解压后，relay 会清理 `settings.json`：指向另一份 `plan` 的 package 条目会被移除，
  `extensions/plan` 保留（relay 内置副本会随 App 更新）；被移除的条目通过
  `relay_restore_done.settingsFixed` 返回，清理失败走 `warning`。
- 恢复仍然是“先自动备份现有数据，再合并解压”，不会丢掉导入前的内容。

## 备份只保留「不可再生」的数据

- `$PREFIX/bin/pig`、`pig-relay` 从来不在备份里（它们在 `$PREFIX/bin`，用安装命令重装）；
- `~/.pig/cache`（编译好的 Go 扩展 runner，几十 MB）、`~/.pig/docs`、日志、crash 输出本来就不打包；
- 新增：relay 自己写的源码副本也不打包——带 `.embedded-hash` 的
  `agent/pigkit/<pkg>` 和 `agent/extensions/plan`，以及 root marker 存在时的 pigkit
  `go.mod`/marker。没有 marker 的用户扩展/包会保留。

因此恢复后**需要重新编译一次**内置扩展（Go build cache 不在备份里，和全新安装一样，
手机上通常几秒到一分钟，relay 启动时在后台完成）。这是有意的：编译产物跟 Go
版本/ABI 绑定，恢复旧 cell 反而可能用到坏缓存。

## 安装脚本：只升不降

`install-termux.sh` 现在比较本地 `pig-relay --version` 和 App 请求的 tag：本地
relay **更新**时保留并提示，不再因为重跑旧 App 的安装命令而把新 relay 降级。

## 升级

1. 装 `app-release.apk`（1.1.35）；
2. Termux 里重跑安装命令（会保留已经是 1.1.35 的 relay）；
3. App → 设置 → 重启 relay。
