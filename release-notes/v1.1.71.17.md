## v1.1.71.17：找到真正的截断点了

上一版（1.1.71.15/16）补的是"收尾帧丢了 → 气泡停在流式状态"，但这次的现场说明不是那个：**`busy` 已经复位、`streamingId` 也是空的**（所以看门狗根本没触发），屏幕上却留着半截原文。

真正的丢点是收尾帧自己：

```kotlin
val id = currentAssistant
if (id == null) { clearLive(); return }   // ← 整帧被丢掉
```

如果一轮对话进行中发生过历史重建（重连、回到前台、切会话、relay 重启都会触发），重建会把 `currentAssistant` 换掉、甚至置空。此后到达的 `message_end` 找不到要写的气泡，**带着完整正文的那一帧被直接丢弃**，屏幕上就只剩最后一次流式刷新的快照——半截、像没解析完的 Markdown。之后任何一次历史重读才会补全，这就是"切会话/过一会儿又好了"。

这一版：

- `message_end` 找不到气泡时**不再丢弃**：依次回退到 `streamingId`、最后的空白助手气泡，都没有就新建一条助手消息把正文收养进来（下一次历史重读会对齐 id）。
- 历史重建不再粗暴覆盖 `currentAssistant`：如果原来那个气泡还在重建结果里，就继续用它。
- 诊断：每轮结束记一行 `[stream] agent_end streaming=… busy=…`；收尾帧收养时记 `[stream] message_end had no bubble; adopted N chars`。日志量是每轮一行，不影响性能。
