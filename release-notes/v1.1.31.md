## 全新 Termux 上只需粘一行命令

全新安装的 Termux 默认 `allow-external-apps=false`，任何 App 发来的 `RUN_COMMAND` 都会在**执行之前**被拒绝 —— 也就是说 App 无法自己把自己装进去。这个版本把这一步拆出来，给你一条**只做这一件事**的一行命令：

```bash
mkdir -p ~/.termux; f=~/.termux/termux.properties; sed -i '/allow-external-apps/d' "$f" 2>/dev/null; echo 'allow-external-apps = true' >> "$f" && termux-reload-settings
```

- 纯 shell，离线可用，不需要先下载任何东西；
- 先删掉旧的/被注释的 `allow-external-apps` 行再追加，跑多少次结果都一样；
- 会调用 `termux-reload-settings`，不用重启 Termux。

在 App 里：设置对话框检测到 Termux 拒绝命令时，会把这条命令单独显示出来，并给出「复制并打开 Termux」按钮（主按钮也变成它）。粘完回到 App 点「一键安装」，就会走有进度条、有退出码反馈的那条路。

同样的事也打包成了一个可读脚本，随每个 release 发布：

```bash
curl -fsSL https://github.com/linuxwff789/pig-android/releases/latest/download/enable-external-apps.sh | sh
```

### English

A fresh Termux refuses every `RUN_COMMAND` before running it (`allow-external-apps=false`), so the app cannot install itself. This release surfaces a one-liner that only flips that switch — plain shell, offline, idempotent — together with a "copy and open Termux" button, after which the in-app install runs with progress and a real exit code. The same logic ships as `enable-external-apps.sh` in every release.
