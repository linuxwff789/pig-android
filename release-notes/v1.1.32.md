## 新装就有完整的界面：默认 UI pack 由 relay 补齐

干净设备上 `~/.pig/android-ui` 之前只有安装脚本 `mkdir` 出来的空目录，relay 推给 App 的 pack
里没有 `manifest.json`，App 只能回一句 **「UI pack 未应用: manifest.json 缺失」** 并退回内置主题
——「模型供应商」窗口、`nav.json` 里的入口一律不出现。

现在 relay 自带 App 的那套默认 pack（`examples/ui-pack-compact` → `relay/embedded/ui`），启动时
**只补缺失文件**（你改过的主题、布局、`nav.json` 一律不动），并且**不包含 `windows/`**：窗口由
拥有它的扩展渲染，`provider-ui` 会按你真实的 `custom-endpoints.json` 写 `windows/providers.json`。

- 验证（全新 HOME）：启动日志 `embedded ui pack: wrote 9 missing file(s)`，随后 App 收到的
  pack 含 `manifest.json` 与 `nav.json`。
- App 侧也改了：万一 relay 实在太旧、推来的 pack 没有 `manifest.json`，App 会保留当前主题并
  提示「relay 版本过旧」，不再弹红色错误。

## 供应商窗口：失败不再假装成功

`/providerui.save` 在「自动获取模型列表」失败时（端点不通、401、离线）以前照样报
**「已添加供应商 …」**，但那个供应商**没有注册进当前会话**，`/model` 里根本选不到——看起来就是
「加不了」。

- 现在会明确报红：`已写入 custom-endpoints.json；但拿不到模型列表（…），当前会话还没注册它。
  点「刷新列表」重试，或关掉「自动获取」手动填模型 ID`。
- 「刷新列表」失败时沿用缓存里的模型列表并重新注册，不会因为一次网络抖动把供应商踢出会话。
- 窗口的表单现在会带上 `headers` / `modelsHeaders`（与 `custom-endpoints` 一致），需要自定义
  头的端点也能从窗口添加。
- App 在收到 `windows/providers.json` 的新推送后会重新拉一次模型列表，保存完立刻能在
  `/model` 里选到。

## 安装脚本：下载失败不再靠运气

- 所有下载重试 3 次；遇到 TLS / HTTP2 断连（curl 退出码 16/18/35/52/53/55/56/92，`53` 正是
  全新 Termux 上见过的那次）自动改走 **HTTP/1.1** 再试。
- 先写 `.part`，校验非空（relay 还校验 ELF magic）后才替换，失败不会留下半截脚本或半个二进制，
  并打印出错的 URL 和 curl 退出码。
- **不带 tag 运行也会升级 relay**：脚本先问 GitHub「latest 是哪个 tag」，再比对
  `pig-relay --version`。以前 `sh install-termux.sh` 见到已有 relay 就直接跳过，于是留在旧
  relay 上，而旧 relay 里没有新的内嵌扩展。
- 扩展探针失败时自动跑一次 `pig update --extensions` 再探一次（缓存的失败构建只有显式重建才会好），
  还不行就提示 `pkg install golang`。
- App 里那条一行安装命令改为：GitHub 失败就换 **jsDelivr**（另一个主机，直接从仓库取同一份脚本），
  并且两个都用 `--retry-all-errors`——普通 `--retry` **不会**重试失败的 TLS 握手，所以
  `curl: (35) TLS connect error: error:00000000:lib(0)::reason(0)` 以前是直接放弃。
- 第二次尝试起自动改用 `--tls-max 1.2 --http1.1`（代理/中间盒常见只对 TLS 1.3/HTTP2 出问题）。
- relay 二进制可用 `PIG_RELAY_MIRRORS="https://ghfast.top/ "` 指定镜像前缀。

## 仓库卫生

`windows/` 属于运行时产物。示例 pack 里曾经躺着从 `~/.pig/android-ui` 拷来的
`windows/providers.json`，于是真实供应商的 id/base URL 跟着 `examples/` 进了 APK。新增
`scripts/check-ui-packs.sh` 并在 CI 中执行：提交 `*/windows/providers.json`（或任何含
`ext:providerui.` / 「个自定义供应商」的 pack 文件）会直接失败。

## 升级

1. 装 `app-release.apk`；
2. Termux 里重跑安装命令（带版本或不带都会升级 relay），然后 App → 设置 → 重启 relay；
3. 已有 `~/.pig/android-ui` 的用户不会被动：只补缺失文件。
