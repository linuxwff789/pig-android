## 现在能看到 relay 和 pig 的报错了，而且实时

以前 App 只看得到 relay 愿意转发的帧：relay 自己的 `logf`（「extensions ready」「cannot start
pig」「plan 没注册上」）和 pig 的 stderr 只写在 Termux 里；而且 pig stderr **只有在它是当前会话
时**才转发。结果是出错当场没反应，重连一次才看到东西。

- relay 的每条 `logf`、pig 的每一行 stderr 都以 `relay_log` 帧发给 App（`source` 为
  `relay`/`pig`，`level` 为 `info`/`error`），pig 的 stderr 不再区分是不是当前会话；
- 最近 **400 行**缓存在 relay 内存里，握手后以 `relay_logs` 回放——启动时编译失败这种
  「连接之前就发生」的错也能看到；
- pig 崩溃时 `relay_exit` 带上 stderr 末尾和最后一行原因，提示从「code 1」变成
  「code 1: 真实原因」；
- App 侧：错误行像 toast 一样即时弹出（同样内容 3 秒内不重复），并全部写进诊断日志。

## 诊断日志：查看、复制、导出到 Download

设置 → 底部「诊断日志」：

- **查看**：每秒刷新最近 400 行，relay / pig / App 三方混排，可选中文本；
- **导出**：写到 **`Download/Pig/pig-log-<时间>.txt`**（Android 10+ 通过 MediaStore，不需要
  权限；更老的系统退回系统文件选择器，同样落在 sdcard），状态行会显示保存位置；
- **复制全部**：日志对话框里一键复制。

日志内容：连接与重连原因、所有进出帧（`relay_ui_pack` 只记 hash + 文件名、`get_messages`
只记条数、流式增量不记）、`RUN_COMMAND` 的 kind/退出码/stdout/stderr、安装与重启动作、
UI pack 应用/拒绝原因、命令与模型数量、所有 notice、用户发出的 prompt（截断）、窗口动作、
切模型。**relay token、apiKey/Authorization、`sk-…` 等密钥在写入前统一打码**，可以直接发给别人。

## 错误信息可以直接复制

- 底部 toast：**长按复制**；
- 聊天里的红色 notice、设置对话框里的安装错误、供应商窗口里的红色状态（`danger`）：选中即可复制；
- 顶部错误横幅：右侧新增复制按钮。

## 补上漏处理的帧

按 pig 的事件文档逐个对过 `AppViewModel.handle()`，这三类之前完全没处理：

- **`extension_error`**（扩展抛异常）：以前静默丢弃，现在变成红色 notice + toast（同一条只提示
  一次）+ 日志，并带上扩展名；
- **`session_info_changed`**（扩展改会话名）：以前要等重连，现在即时更新抽屉里的名字；
- **`summarization_retry_*`**（摘要重试）：以前只有 `auto_retry*` 有状态，现在显示
  `summarizing` 并在结束时清空。

保持不处理的：`turn_end`（`message_end`/`agent_end` 已收尾）、`bash_execution_update`（App 不用
那个 RPC）、`queue_update`（队列数以 `get_state` 为准）、`entry_appended`（没有对应 UI）、
`relay_projects`（App 还没有项目选择器）。

## 升级

1. 装 `app-release.apk`（1.1.33）；
2. Termux 里重跑安装命令升级 `pig-relay`（不带 tag 也会解析 latest 并升级），然后 App →
   设置 → 重启 relay；
3. 已有 `~/.pig/android-ui` 不会被改动，只补缺失文件。
