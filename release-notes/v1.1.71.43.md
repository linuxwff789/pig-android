## v1.1.71.43：修好搜索跳转（id 对不上的真正原因）

**为什么之前点了还是不跳**
- 上一版让 relay 把会话文件里的「消息 id」补回给 App，但判断「消息是否已有 id」时只检查这段 JSON 里有没有 `"id":` 字样——工具参数、正文里的 JSON 几乎都带这个字样，于是补写被跳过。
- 结果 App 拿到的还是 pig 运行时的消息 id，与会话文件里搜索命中的 id 不一致，定位永远失败。

**这次**
- relay 改为直接解析消息对象，**总是**用会话文件那一行的 id 和时间戳覆盖，保证历史与搜索用的是同一个键。
- App 额外加了一层兜底：即使 id、时间戳都对不上（比如 relay 还是旧版本），也会用命中的那段文字去匹配消息正文、思考和工具结果，找到并滚动过去。

**怎么验证**
- 搜索后点任意一条结果，应该跳到对应消息，行首显示命中片段，当前命中行保持高亮并展开它所在的折叠内容。
- App 日志里会多一行 `search locate id=… at=… -> 索引/总数`，可以确认定位是否命中。

relay 与 APK 都要更新。id 补写在 relay 侧，更新后请重启一次 relay（设置 → 重启 relay），否则只能靠文字兜底。
