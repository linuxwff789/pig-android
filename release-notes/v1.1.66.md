## 不会把你换回正式版

你担心的是「我在预览版上，更新时会不会反而拿到正式版（v1.1.63，比现在的 1.1.65 还旧）」。
逐条核对过，都不会：

1. **检查更新**：首选 `releases.atom`，这个 feed 有预览版（现在第一条是 v1.1.65）。
   只有当 atom 打不开时才退到 `/releases/latest` 的跳转 —— 那个指向最后一个**正式版**（v1.1.63）。
   这次修掉了这里的隐患：那个跳转结果**只有在确实比当前版本新时才采用**，否则先问「release 列表接口」
   （包含预览版），跳转只作最后的兜底。
   而且版本比较用的是 tag，本来就只会把「更新」当更新，旧版本不会出现在更新弹窗里。
2. **安装脚本**（Termux 侧）：带版本参数时（App 一键安装会传自己 tag）脚本里有守卫 ——
   已装的 relay 比目标版本新就保留、不降级；解析不到最新 tag 时也**不会重装**（直接保留现有的）。
   不带参数时用 API 列表解析**最新（含预览版）**。
3. **App 内「复制 Termux 更新命令」**：取的是仓库 main 上的脚本，同样解析最新（含预览版），不 pin 版本。

唯一会出现正式版的场景：全新设备 + 完全解析不到最新 tag（GitHub API 和跳转同时失败），
这时脚本回落到 `/releases/latest` 的资产（v1.1.63）。这只影响首次安装，且不会覆盖更旧的现有 relay。

装 `app-release.apk`（1.1.66）即可；relay 无改动。
